### 10. Assessment engine: our own system with replaceable tools

Own the workflow tests, orchestration, evidence format, review process, and reporting. Integrate mature tools where useful. Do not train a foundation model or rebuild general-purpose scanners as a prerequisite.

Architecture: public website and authenticated workspace → application API and authorization → project and queue store → scoped assessment jobs → isolated runner → approved client environment → evidence store → review → report and retest.

The first release must include a local synthetic support-agent fixture with two customers, fake orders, and a refund endpoint. It must demonstrate one intentionally vulnerable authorization path and a corrected path. Tests should establish whether the server performed an unauthorized action, not merely whether the model sounded compliant.

Build an adapter interface for future scanners, AI testing tools, client APIs, and model providers. Each adapter declares capabilities, required access, data destinations, expected costs, and execution limits. Implement the synthetic adapter fully. Keep unavailable production adapters explicitly unavailable.

LLMs may suggest test variations, summarize traces, or draft explanations. Deterministic checks and human investigation establish consequential findings. Do not auto-publish model judgments as confirmed vulnerabilities. External model calls require configured providers and engagement-specific permitted data handling. Model selection sits behind an adapter; business logic must not depend on a single AI vendor.

The runner must enforce approved target allowlists, request and time budgets, concurrency limits, test windows, credentials, and stop conditions. It only ever operates against systems named in a signed authorization within its window. Keep it separate from the public web process. Record cancellation and partial execution honestly. Require a new scope decision for any new target.

Handle redirects, DNS resolution, internal-address access, and URL fetching so a submitted URL cannot turn the server into an unrestricted network scanner. Deny private, loopback, link-local, and cloud-metadata destinations by default. Private-network testing, if implemented, requires an explicitly configured customer-side runner. Support safe cancellation and human review before consequential operations.

Evidence record fields: organization, engagement, run ID, test ID and version, timestamp, target configuration, sanitized request or action trace, observed outcome, expected rule, source tool and version, artifact digest, limits, and reviewer. Preserve provenance. Redact sensitive values before client-visible reporting or external model use.

The reverse-engineer-anything workflow is optional, for client-supplied artifacts or captures the client is authorized to analyze. Do not invoke it on unrelated software. Preserve artifact identity, observations, inferences, unknowns, and tool limitations when that analysis is used. Its absence must not block ordinary API or workflow assessment.
